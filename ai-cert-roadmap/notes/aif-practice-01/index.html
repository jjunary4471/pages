02오답 8문

태스크 번호는 도메인 점수표로 확실히 짝지어지는 문항에만 적었습니다(Q6·Q7·Q13·Q14 는 1.1·2.3·3.3 중 하나). 8문 가운데 4문은 이름이 비슷한 서비스를 헷갈려서 틀렸습니다. 서비스 구별은 AWS 서비스 사전의 묶음 비교표로 복습합니다.

Q6순서 지정 · SageMaker 추론 · 37초
SageMaker AI 추론 옵션 세 가지를 지연 시간이 짧은 순서로 놓기.
내 답: 배치 변환 → 실시간 → 비동기
정답과 이유
실시간 추론→비동기 추론→배치 변환
  • 실시간: 항상 켜진 엔드포인트가 바로 응답 (밀리초~초)
  • 비동기: 큐에 넣고 끝나면 S3 에 결과 + 알림 (분 단위까지)
  • 배치 변환: 데이터셋 전체를 한꺼번에, 엔드포인트 없음 (가장 느림)
기억법: 결과를 지금 / 이따가 / 전부 끝나고 받는 순서.

Q123.4 FM 성능 평가 · 16초
텍스트 생성용 FM 의 성능을 평가할 지표 고르기.
내 답: F1 점수
정답과 이유
ROUGE
  • ROUGE: 생성·요약한 글이 기준 글과 얼마나 겹치는지 → 텍스트 생성·요약 평가
  • F1: 정밀도와 재현율의 조화 평균 → 분류 모델 평가
  • 미세 조정·강화 학습은 모델을 바꾸는 방법이지 평가 지표가 아님
지표 짝: 요약·생성 = ROUGE · 번역 = BLEU · 의미 유사도 = BERTScore · 분류 = 정확도/F1 · 회귀 = RMSE
Q13FM 접근 방법 · 14초
오픈 소스 FM 으로 계약서가 규정을 지키는지 검토하려면 어떤 서비스?
내 답: Amazon Q Business
정답과 이유
Amazon SageMaker JumpStart
  • JumpStart 는 사전 훈련된 오픈 소스 모델을 골라 SageMaker 에 배포하는 모델 허브
  • Q Business 는 완성형 어시스턴트 — 모델을 고를 수 없고 오픈 소스도 아님
  • Textract(문서 글자 추출), Kendra(검색)는 FM 을 제공하지 않음
핵심어 “오픈 소스 FM” → JumpStart. 14초 만에 골랐다면 이 단어를 놓친 것.
Q14AI 서비스 구별 · 37초
콜 센터 녹음에서 도메인 용어가 들어간 음성의 받아쓰기 정확도를 높이려면?
내 답: Amazon Translate 사용자 지정 언어 모델
정답과 이유
Amazon Transcribe 사용자 지정 언어 모델
  • 받아쓰기(음성→텍스트)는 Transcribe. 도메인 텍스트로 사용자 지정 언어 모델을 만들거나 사용자 지정 어휘를 넣으면 전문 용어 정확도가 오름
  • Translate 는 번역 — 음성을 다루지 않음
  • Transcribe 의 언어 식별은 “무슨 언어인지” 알아낼 뿐 정확도 개선이 아님 · Lex 는 챗봇
Transcribe = 받아 적기(scribe) · Translate = 번역
Q155.2 거버넌스 · 7초
Bedrock API 호출을 누가, 언제 했는지 로그로 남기려면?
내 답: Amazon CloudWatch
정답과 이유
AWS CloudTrail
  • CloudTrail: API 이벤트, 호출한 사용자, 시간까지 기록하는 감사 로그
  • CloudWatch: 호출 수·지연 같은 지표는 보지만 “어떤 사용자가” 는 모름
  • Inspector(취약점), Trusted Advisor(모범 사례 점검)는 호출 기록과 무관
7초 만에 틀렸습니다. “누가” 가 보이면 Trail(발자국) — 누가 지나갔는지 남는 흔적.
Q163.3 미세 조정 · 16초
명령(instruction) 기반 미세 조정에 맞는 데이터 형식은?
내 답: 카테고리 레이블이 붙은 이미지
정답과 이유
프롬프트-응답 텍스트 쌍
  • 명령 기반 미세 조정 = “이런 지시에는 이렇게 답한다” 를 보여 주는 레이블 있는 프롬프트-응답 쌍
  • 레이블 붙은 이미지는 이미지 분류(Rekognition Custom Labels 같은) 훈련용
짝으로 기억: 미세 조정 = 레이블 있음(프롬프트-응답) · 지속적 사전 훈련 = 레이블 없음(도메인 원문 텍스트)
Q181.3 ML 수명 주기 · 복수 선택 · 27초
훈련 데이터셋의 변수 수를 늘려 모델 성능을 높이려면 어떤 파이프라인 단계? (2개)
내 답: 데이터 수집 ✅ + 모델 모니터링 ❌
정답과 이유
데이터 수집 + 특성 엔지니어링
  • 데이터 수집: 원시 데이터를 더 모으면 변수가 늘 수 있음
  • 특성 엔지니어링: 기존 데이터에서 새 특성을 만들고 변환·선택 → 변수 수를 직접 늘림
  • 모델 모니터링은 배포 뒤 드리프트를 감시하는 단계, 하이퍼파라미터 튜닝은 알고리즘 동작 조정, 모델 평가는 훈련 뒤 측정
ML 수명 주기 순서: 문제 정의 → 데이터 수집 → 전처리 → 특성 엔지니어링 → 훈련·튜닝 → 평가 → 배포 → 모니터링
Q194.2 투명성 · 24초
모델의 용도, 위험 등급, 훈련 세부 정보, 평가 결과를 기록할 SageMaker 기능은?
내 답: SageMaker Model Monitor
정답과 이유
SageMaker Model Cards
  • Model Cards: 모델 정보를 한 곳에 문서화 → 투명성·설명 가능성
  • Model Monitor: 운영 중 품질·드리프트 감시 · Model Dashboard: 모든 모델 조회 · Role Manager: 권한
“기록·문서화·위험 등급” → 카드(Card)에 적는다.
