01이번 주 개요

로드맵에는 "Exam Prep Standard 전반부 모듈 1~2"라고 적혀 있지만, 2026-11-14에 확인해 보니 Skill Builder의 AIF 시험 준비 자료는 도메인별 강의로 개편되었습니다. 무료인 Domain 1~5 Review(각 1시간 30분)와 유료 구독용 Domain Practice(30~55분)로 나뉘어 있습니다. 그래서 이번 주는 "전반부" 대신 Domain 1 Review 한 과정을 끝까지 듣는 것으로 바꿨습니다. Domain 2 이후는 4주차부터 1단계에서 정식으로 다룹니다.

Domain 1 Review는 90분입니다. 1.5배속으로 보면 60분이라 월·화·목 20분 블록 세 개에 딱 들어갑니다. 수요일은 강의 대신 Bedrock 콘솔 실습, 금요일은 새 내용 없이 용어 정리와 복습입니다. 1주차에 만든 Claude Project "AI 자격증 공부"와 weekly-review 스킬을 이번 주에 실제로 씁니다.

  • 데이터 종류: 레이블 있음/없음, 정형(표)/비정형(텍스트·이미지), 시계열. 이 구분이 다음 날 배우는 학습 방식을 정함

03심화 · 복습 방법

도메인 1은 "아는 단어"가 많아서 들었으니 안다는 착각이 가장 쉽게 생기는 도메인입니다. 실제 시험은 정의를 묻지 않고 상황에 대입하게 합니다. 그래서 복습은 용어 외우기가 아니라 내 업무 예시에 대입해 말로 설명하기로 합니다. 방식은 1주차와 같은 30분 규칙입니다.

금요일 복습 루틴 (30분)

  1. 5분 — 12줄 메모 통독. 막히는 문장에 표시만 한다
  2. 5분 — 동심원 그림(AI ⊃ ML ⊃ 딥러닝 ⊃ 생성형 AI)과 ML 파이프라인을 아무것도 보지 않고 다시 그린다
  3. 10분 — 자기 테스트 10문. 답을 열기 전에 소리 내어 설명하고 막힌 번호를 적는다
  4. 5분 — 막힌 문항에 해당하는 강의 그 부분만 다시 본다 (전체 재시청 금지)
  5. 5분 — 한 장 압축 메모 완성 + 다음 주 월요일 첫 20분 할 일 한 줄

심화 이해 포인트

왜 "AI가 맞지 않는 경우"를 묻는가 — 비용과 확실성

ML은 확률적인 예측을 내놓습니다. 그래서 같은 입력에 늘 같은 정답이 필요한 일(세금 계산, 권한 검사)에는 규칙 기반 코드가 더 싸고 정확합니다. 시험이 이걸 묻는 이유는, 실제 현장에서 가장 비싼 실수가 "AI가 필요 없는 곳에 AI를 쓰는 것"이기 때문입니다. 이 감각은 6단계 Google Generative AI Leader(83~85주차)의 비즈니스 판단 문제까지 이어집니다.

  • 스스로 실험: 내 업무에서 지금 규칙 기반 코드로 처리하는 것 하나를 골라, ML로 바꾸면 무엇이 좋아지고 무엇이 나빠지는지 두 줄씩 적기
  • 메모에 적을 한 줄: "정답이 정해져 있으면 코드, 패턴을 찾아야 하면 ML"

추론 방식 4가지와 백엔드 아키텍처

실시간·배치·비동기·서버리스 추론은 백엔드 개발자에게 익숙한 동기 API · 배치 잡 · 큐 · Lambda와 거의 같은 구조입니다. 모델이 무거워졌을 뿐입니다. 이 대응을 지금 잡아 두면 2단계 MLA(11~26주차)의 SageMaker 엔드포인트 종류가 외울 것이 아니라 고를 것이 됩니다.

  • NestJS 서비스 하나를 골라, 그 안의 처리 4개를 추론 방식 4가지에 각각 대응시키는 표 만들기
  • "요청은 지금 받고 결과는 나중에 알려 준다" = 어떤 추론 방식인지 한 단어로

토큰 = 돈 = 지연 시간

수요일에 본 입력·출력 토큰 수는 Bedrock 요금 계산의 단위이면서, 답이 늦게 오는 이유이기도 합니다. 1주차에 배운 컨텍스트 창도 결국 토큰 상한입니다. 3단계 GenAI Developer Pro(27~52주차)의 비용 최적화·프롬프트 캐싱 문제는 전부 이 한 줄에서 시작합니다.

04자기 테스트

금요일과 다음 복습 시점에 풉니다. 답을 열기 전에 먼저 소리 내어 설명해 보고, 막힌 문항은 번호를 메모에 적어 둡니다.

1. AI · ML · 딥러닝 · 생성형 AI의 포함 관계를 설명하고, 각각의 예를 하나씩 들면?
AI가 가장 넓고, 그 안에 데이터로 규칙을 배우는 ML, 그 안에 깊은 신경망을 쓰는 딥러닝, 그 안에 새 내용을 만드는 생성형 AI가 있다. 예: 규칙 기반 챗봇 / 스팸 분류 / 이미지 인식 / 문장 생성 LLM.
2. 추론 방식 4가지(실시간·배치·비동기·서버리스)를 각각 어떤 상황에 쓰나?
실시간은 즉시 답이 필요할 때(결제 사기 탐지), 배치는 대량을 한꺼번에(야간 점수 계산), 비동기는 처리가 길어 나중에 결과를 받을 때(긴 문서 분석), 서버리스는 요청이 드문드문 와서 서버를 상시로 두기 아까울 때.
3. 지도 · 비지도 · 강화 학습을 "데이터에 무엇이 있나" 기준으로 구분하면?
지도 학습은 정답 레이블이 있는 데이터, 비지도 학습은 레이블 없이 구조만 찾는 데이터, 강화 학습은 행동에 대한 보상 신호로 배운다.
4. 회귀 · 분류 · 군집을 각각 한 줄 예시와 함께 구분하면?
회귀는 숫자를 예측(다음 달 매출), 분류는 정해진 범주 중 하나를 고름(스팸/정상), 군집은 정답 없이 비슷한 것끼리 묶음(구매 패턴별 고객 그룹).
5. AI/ML을 쓰면 안 되는 경우 두 가지는?
비용이 얻는 가치보다 클 때, 그리고 예측이 아니라 항상 정확히 같은 결과가 필요할 때(세금 계산, 권한 판정). 이런 경우는 규칙 기반 코드가 낫다.
6. Transcribe · Translate · Comprehend · Lex · Polly를 각각 한 마디로?
Transcribe 음성→텍스트, Translate 번역, Comprehend 텍스트에서 감정·핵심어 추출, Lex 대화형 챗봇, Polly 텍스트→음성.
7. ML 파이프라인 단계를 순서대로 말하고, 배포 뒤에도 할 일이 있는 이유는?
수집 → 전처리·특성 공학 → 학습 → 평가 → 배포 → 모니터링 → 재학습. 실제 데이터가 학습 때와 달라지면 성능이 떨어지므로 감시하고 다시 학습해야 한다.
8. 정밀도와 재현율의 차이와, 재현율이 더 중요한 예는?
정밀도는 "맞다고 한 것 중 진짜 맞은 비율", 재현율은 "진짜 맞는 것 중 찾아낸 비율". 사기 탐지·암 검진처럼 놓치면 큰일 나는 문제는 재현율이 중요하다.
9. Bedrock과 SageMaker AI는 무엇이 다른가? 수요일 실습으로 설명하면?
Bedrock은 이미 만들어진 파운데이션 모델을 API로 바로 쓰는 서비스이고, SageMaker AI는 모델을 직접 학습·배포하는 플랫폼이다. 수요일에는 서버나 학습 없이 콘솔에서 바로 모델을 호출했으니 Bedrock의 방식이다.
10. 이번 주 내용 ↔ 시험 용어를 세 쌍 이상 짝지어 보라.
포함 관계 그림 ↔ 태스크 1.1 기본 개념 / 서비스 짝짓기 카드 ↔ 태스크 1.2 관리형 AI 서비스 / 파이프라인 순서 ↔ 태스크 1.3 MLOps / Bedrock 토큰 수 ↔ 태스크 2.1 토큰 기반 요금 / temperature ↔ 추론 파라미터(도메인 3).
