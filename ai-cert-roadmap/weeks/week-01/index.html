01이번 주 개요

Claude 101은 "Claude를 일에 쓰는 법" 입문 과정입니다. 1단계(AWS AI Practitioner)의 생성형 AI 기초 도메인(프롬프트, 컨텍스트, 토큰, RAG 개념)을 제품 수준에서 먼저 몸으로 익히는 역할이라, 여기서 만든 Project·Skill은 104주 내내 공부 도구로 씁니다.

총 강의 시간이 약 2.5시간이라 5일 × 30분과 딱 맞지만, 실습·퀴즈 시간이 따로 필요합니다. 강의는 1.25~1.5배속으로 보고 20분 블록 안에서 끝내는 것을 기본으로, 넘치면 주말 보충으로 넘깁니다.

개념학습 내용

  • Claude가 무엇인가: 대화형 모델이 아니라 "문서·코드·표를 함께 만드는 작업 도구"로 소개됨. 학습 데이터 기준일(knowledge cutoff)이 있고, 모르는 것은 모른다고 하도록 만들어져 있음
  • 첫 대화: 한 번에 다 요구하지 않고, 결과를 보고 고쳐 달라고 하는 반복(iteration)이 기본 사용법
  • 좋은 결과를 얻는 법: 목표(goal) · 맥락(context) · 제약(constraints) · 출력 형식(format) 네 가지를 밝히면 결과가 달라짐. 예시(example)를 붙이면 더 좋아짐
  • 1단계 AIF 연결: 이게 시험 용어로 프롬프트 엔지니어링, 예시를 붙이는 것이 few-shot, 모르는 것을 지어내는 것이 환각(hallucination)

03심화 · 복습 방법

Claude 101은 내용이 어렵지 않아서 "들었으니 안다"는 착각이 생기기 쉽습니다. 그래서 복습은 다시 보기가 아니라 안 보고 꺼내기로만 합니다. 로드맵의 30분 규칙(금요일 = 오답·주간 메모)과 같은 방식이며, 이 틀은 104주 동안 유지됩니다.

금요일 복습 루틴 (30분)

  1. 5분 — 12줄 메모 통독. 이해 안 되는 문장에 표시만 하고 멈추지 않는다
  2. 5분 — 제품 지도를 아무것도 보지 않고 다시 그린다. 목요일 그림과 비교해 빠진 상자를 적는다
  3. 10분 — 자기 테스트 10문. 답을 열기 전에 소리 내어 설명. 막힌 번호 기록
  4. 5분 — 막힌 문항에 해당하는 강의만 그 부분을 다시 본다 (강의 전체 재시청 금지)
  5. 5분 — 한 장 압축 메모 완성 + 다음 주 월요일 첫 20분 할 일 한 줄

왜 Project가 필요한가 — 컨텍스트라는 자원

모델은 대화 한 번에 읽을 수 있는 양(컨텍스트 창)이 정해져 있고, 대화가 끝나면 그 내용을 기억하지 않습니다. Project는 "매번 다시 알려 줘야 하는 것"을 밖에 꺼내 두는 장치입니다. 이것을 알면 1단계 AIF 도메인 2의 컨텍스트 창 · 토큰 · 시스템 프롬프트가 외울 용어가 아니라 이미 써 본 것이 됩니다.

  • 스스로 실험: Project 밖에서 "내 배경을 모른 채" 같은 질문을 던져 답이 얼마나 일반적인지 비교
  • 메모에 적을 한 줄: "Project 지침 = 시스템 프롬프트, Project 파일 = 작은 RAG"

Skill vs Project 지침 vs 그냥 프롬프트

세 가지 모두 "미리 적어 두는 지시"입니다. 구분은 범위입니다. 한 번 쓰면 프롬프트, 한 주제 안에서 계속 쓰면 Project 지침, 주제와 상관없이 같은 절차를 반복하면 Skill. 이 구분을 못 하면 Project 지침이 비대해지고 Skill은 안 만들게 됩니다.

  • 수요일에 만든 weekly-review 스킬이 왜 Project 지침이 아니라 Skill이어야 하는지 한 문장으로 설명해 보기
  • 반대로 "한국어로 짧게 답해"가 왜 Skill이 아니라 Project 지침인지도

도구 연결과 그라운딩 — 2년 뒤까지 이어지는 줄기

Connectors(도구를 쓰는 모델)와 Research(출처를 찾아 답하는 모델)는 3단계 GenAI Developer Pro의 에이전트 · RAG · 그라운딩 체크, 7단계 Azure의 AI Search까지 같은 줄기입니다. 1주차에 "출처를 열어 숫자를 확인한다"는 습관을 들이면 나중에 평가(evaluation) 단원이 쉬워집니다.

주말 심화 과제 선택

밀린 날이 있으면 보충이 먼저입니다. 다 했다면 하나만 고릅니다.

① 반복 작업 하나를 끝까지 자동화
실제 업무에서 매주 하는 일 하나(예: 주간 보고 초안, PR 설명 정리)를 Project + Skill + Artifact로 끝까지 만들어 월요일에 실제로 쓴다. 강의의 "하나의 반복 과제에 모든 강의를 적용하라"는 조언 그대로
② Claude Code 쪽 깊이 보기
이 로드맵 페이지와 주차 페이지를 만든 cert-week-page 스킬의 SKILL.md를 읽고, 강의의 Skills 개념이 파일로는 어떻게 생겼는지 비교. 그리고 2주차 페이지를 그 스킬로 미리 생성해 본다
③ AIF 도메인 2 미리 맛보기
AWS 공식 시험 가이드(AIF-C01)의 도메인 2 "생성형 AI 기초" 항목 목록만 읽고, 이번 주 강의에서 이미 본 개념에 체크. 절반 이상 체크되면 4주차가 가벼워진다
④ 밀린 것 보충
퀴즈 미통과, 못 본 강의, 못 만든 스킬이 있으면 이것이 1순위. 새 과제는 하지 않는다

04자기 테스트

금요일과 다음 복습 시점에 풉니다. 답을 열기 전에 먼저 소리 내어 설명해 보고, 막힌 문항은 번호를 메모에 적어 둡니다.

1. 좋은 프롬프트의 네 요소를 말하고, 각각이 빠졌을 때 답이 어떻게 나빠지는지 예를 하나씩 들어 보라.
목표(무엇을 원하나) · 맥락(누가, 어떤 상황) · 제약(길이·언어·금지 사항) · 출력 형식(표·목록·코드). 목표가 없으면 엉뚱한 방향, 맥락이 없으면 일반론, 제약이 없으면 길고 장황, 형식이 없으면 다시 정리해야 하는 답이 나온다.
2. Claude가 사실이 아닌 내용을 자신 있게 말할 수 있는 이유와, 사용자가 해야 할 대응은?
다음에 올 그럴듯한 말을 만드는 모델이라 "모른다"보다 "그럴듯한 답"이 나올 수 있다(환각). 대응: 사실·숫자·출처는 확인하고, 모르면 모른다고 하라고 지침에 적고, Research처럼 출처가 붙는 방식을 쓴다.
3. Project의 지침(instructions)과 파일(knowledge)은 각각 무엇을 담당하나?
지침은 "어떻게 답할지"(역할·톤·규칙, 시스템 프롬프트에 해당), 파일은 "무엇을 근거로 답할지"(참고 문서, 작은 RAG에 해당).
4. Artifact로 받는 것이 더 나은 결과물의 조건은?
다시 쓰거나 공유할 결과물(문서·코드·웹페이지·표)이고, 여러 번 고쳐 가며 다듬을 것일 때. 한 번 읽고 끝날 답은 채팅으로 충분하다.
5. Skill을 만들어야 할 신호는? Project 지침과 어떻게 구분하나?
주제와 상관없이 같은 절차를 두 번 이상 설명하고 있다면 Skill. 한 주제(프로젝트) 안에서만 통하는 규칙이면 Project 지침. 범위로 구분한다.
6. 커넥터를 연결할지 판단하는 기준 한 문장은?
실제 수작업 한 단계를 없애 줄 때만 연결한다. 그렇지 않으면 권한만 늘어난다.
7. Research 모드가 일반 답과 다른 점 두 가지와, 결과를 받은 뒤 반드시 할 일은?
여러 출처를 찾아 종합하고 출처를 붙인다. 시간이 더 걸린다. 받은 뒤에는 출처를 열어 숫자·주장을 확인한다(그라운딩 확인).
8. Enterprise search는 무엇이고, 개인 계정에서 쓸 수 없는데 왜 알아 둬야 하나?
조직 내 문서·메시지·위키를 한 번에 검색해 답하는 기능. "흩어진 문서를 검색해서 답한다"는 구조가 AWS Kendra·Bedrock Knowledge Base, Azure AI Search와 같아서 시험과 실무에 그대로 나온다.
9. Claude Chat · Claude Code · Cowork · API를 각각 어떤 일에 쓰나?
Chat은 대화·문서·분석, Claude Code는 터미널에서 코드베이스를 읽고 고치는 일, Cowork는 파일·업무 흐름 자동화, API(Platform)는 내 서비스 안에 Claude를 내장할 때.
10. 이번 주 내용 중 1단계 AWS AI Practitioner 시험 용어로 바로 이어지는 것을 세 쌍 이상 짝지어 보라.
네 요소 프롬프트 ↔ 프롬프트 엔지니어링, 예시 붙이기 ↔ few-shot, 지어내기 ↔ 환각, Project 파일 ↔ RAG, Project 지침 ↔ 시스템 프롬프트, 커넥터 ↔ 도구 사용·에이전트, Research 출처 확인 ↔ 그라운딩, Enterprise search ↔ Kendra·Knowledge Base.
