01이번 주 개요

OpenAI Academy 의 AI Foundations 는 ChatGPT 를 업무에 제대로 쓰는 습관을 다루는 무료 자기 주도 강좌입니다. 공식 도움말 기준 예상 시간은 60~75분이고, 주제는 AI 기초 · 더 분명한 프롬프트 · 쓸모 있는 컨텍스트 주기 · 출력 검토 · 책임 있는 사용 다섯 가지입니다. 강좌 안의 레슨 개수와 제목은 로그인 없이 확인하지 못했습니다(확인 필요).

끝에는 평가가 있습니다. 문제은행 50문에서 10~20문이 나오고 80% 이상이면 배지(Accredible 발급)를 받습니다. 떨어지면 새로 섞인 문제로 다시 볼 수 있습니다. 주의할 점: 로드맵에 적은 "수료증"은 강좌 하나로는 나오지 않습니다. 수료증(certificate)은 Foundations 경로의 세 강좌(AI Foundations · Applied AI Foundations · Agents and Workflows)를 모두 통과해야 나오므로, 이번 주 목표는 배지로 잡고 나머지 두 강좌는 여행 뒤 주말 선택 과제로 둡니다.

왜 이 강좌가 AWS 시험 사이에 있나: 프롬프트 · 컨텍스트 · 할루시네이션 · 사람 검토는 AIF-C01 도메인 3 태스크 3.2(프롬프트 엔지니어링)와 도메인 4(책임감 있는 AI)의 바탕입니다. 지난주 연습 문제에서 맞힌 퓨샷 · RAG 문제가 여기서 "왜 그런지"로 연결됩니다.

이번 주 목표
  • AI Foundations 강좌를 끝까지 듣고, 다섯 주제를 내 업무 예시로 한 줄씩 설명할 수 있다
  • 평가를 80% 이상으로 통과해 배지를 받고 전리품 페이지에 올린다
  • 같은 업무 요청을 "전 / 후" 프롬프트로 써 보고, 결과가 왜 달라졌는지 적는다
  • 다음 주(4주차) 1단계 AIF-C01 교재를 주문하고 첫 장 제목을 적어 둔다

심화 이해 포인트

왜 두 회사(Anthropic · OpenAI)가 같은 말을 하는가 — 모델이 아니라 사용법이 차이를 만든다

1주차 Claude 101 과 이번 주 AI Foundations 는 결국 같은 이야기를 합니다: 목표를 분명히, 컨텍스트를 충분히, 결과는 사람이 검토. 이유는 모든 LLM 이 같은 원리(다음 토큰 예측)로 움직이기 때문입니다. 모델을 바꾸는 것보다 입력을 바꾸는 것이 싸고 빠릅니다. 이 순서(프롬프트 → RAG → 미세 조정)는 AIF-C01 7주차(12/21) "파인튜닝 vs RAG"와 3단계 AIP-C01(27주차~)의 비용 문제로 그대로 이어집니다.

  • 스스로 실험: 같은 전/후 프롬프트를 ChatGPT 와 Claude 에 각각 넣고, 모델 차이와 프롬프트 차이 중 어느 쪽이 결과를 더 바꿨는지 한 줄로 적기

출력 검토 = 사람이 하는 평가

"결과를 검토하라"는 말은 시험에서 human-in-the-loop, 할루시네이션 대응, 모델 평가로 나뉘어 나옵니다. 지난주 오답 Q12(ROUGE)는 이 검토를 숫자로 자동화한 것이고, Bedrock 의 모델 평가에는 사람 평가 작업도 있습니다. 즉 이번 주의 "검토 습관"은 AIF 도메인 3 태스크 3.4 의 손으로 하는 버전입니다.

  • 메모에 적을 한 줄: "사람이 하면 검토, 숫자로 하면 평가 지표(ROUGE·BLEU), 모델이 하면 LLM-as-a-judge"

주말 심화 과제 선택

밀린 날이 있으면 보충이 먼저입니다. 다 했다면 하나만 고릅니다.

① Applied AI Foundations (선택)
Foundations 경로 두 번째 강좌. 좋은 프롬프트를 반복 가능한 워크플로(입력·모델·도구·체크포인트·사람 검토)로 바꾸는 내용입니다. 세 강좌를 모두 통과해야 경로 수료증이 나옵니다
② Agents and Workflows (선택)
경로 세 번째 강좌. 에이전트에게 컨텍스트·출력·경계를 주고 결과를 검토하는 법. AIF 7주차의 Bedrock Agents 와 연결됩니다
③ 연습 문제 Q7 캡처
Skill Builder 연습 문제 결과 화면에서 비어 있던 7번 연결 문제를 캡처해 오답 노트를 채웁니다
④ 밀린 것 보충
평가를 아직 통과하지 못했거나 교재를 주문하지 못했다면 이것이 1순위입니다. 새 과제는 하지 않습니다

04자기 테스트

금요일과 다음 복습 시점에 풉니다. 답을 열기 전에 먼저 소리 내어 설명해 보고, 막힌 문항은 번호를 메모에 적어 둡니다.

1. LLM 이 그럴듯하지만 틀린 답을 내는 이유를 한 문장으로 설명해 보라.
모델은 사실을 찾아보는 것이 아니라 다음에 올 토큰을 확률로 예측하기 때문입니다. 그래서 확률상 자연스러운 문장이 사실과 다를 수 있고, 이것을 할루시네이션이라고 합니다.
2. 좋은 프롬프트의 다섯 요소를 말하고, 내 업무 예시 하나에 대입해 보라.
목표 · 대상 독자 · 형식 · 제약(길이·톤·금지 사항) · 예시. 예: "신규 입사자(독자)에게 배포 절차를 알려 주는(목표) 5단계 체크리스트(형식)를 300자 이내, 사내 서버명은 빼고(제약), 아래 예시 문체로(예시)".
3. 컨텍스트를 붙여 주는 것과 퓨샷 예시를 보여 주는 것은 각각 무엇을 바꾸나?
컨텍스트는 모델이 모르는 사실·자료를 채워 답의 내용을 바꿉니다. 퓨샷 예시는 원하는 형식·문체를 보여 줘 답의 모양을 바꿉니다.
4. 사람이 컨텍스트를 붙여 주는 일을 시스템이 자동으로 하면 무엇이라 부르나? AWS 에서 무엇으로 만드나?
검색 증강 생성(RAG). 질문과 관련된 문서를 먼저 찾아 프롬프트에 붙인 뒤 답하게 합니다. AWS 에서는 Bedrock Knowledge Bases 로 만들 수 있습니다.
5. 출력을 검토할 때 반드시 확인할 세 가지는?
숫자·날짜 같은 사실, 인용·출처, 그리고 개인정보나 편향된 표현이 들어가지 않았는지. 최종 판단과 책임은 사람이 집니다.
6. AI 에 넣으면 안 되는 정보의 예를 세 가지 들어 보라.
고객 개인정보(이름·연락처), 회사 기밀(미공개 계획, 계약 조건), 인증 정보(비밀번호, API 키). 회사의 데이터 정책이 허용하는 도구인지 먼저 확인합니다.
7. "human in the loop" 는 무엇이고, 어떤 업무에 꼭 필요한가?
AI 결과를 사람이 확인·승인하는 단계를 흐름 안에 두는 것입니다. 고객에게 나가는 문서, 금액·법률·의료 판단처럼 틀리면 비용이 큰 업무에 필요합니다.
8. 프롬프트 개선 → RAG → 미세 조정을 비용·노력 순으로 놓고, 각각 언제 쓰는지 한 줄씩.
프롬프트 개선(가장 쌈): 형식·지시를 바꾸고 싶을 때. RAG(중간): 최신·사내 지식이 필요할 때. 미세 조정(가장 비쌈): 특정 문체·작업을 모델 자체에 익히게 해야 할 때.
9. OpenAI Academy 의 배지와 수료증은 어떻게 다른가?
배지는 강좌 하나를 마치고 평가를 80% 이상으로 통과하면 받습니다. 수료증은 경로(예: Foundations 세 강좌)를 모두 통과해야 받습니다. 둘 다 공인 자격증(certification)은 아닙니다.
10. 이번 주 내용 ↔ AIF-C01 시험 용어를 세 쌍 이상 짝지어 보라.
예시를 보여 주기 ↔ 퓨샷 프롬프팅(태스크 3.2) · 자료를 붙여 주기 ↔ RAG(태스크 3.1) · 틀린 답 ↔ 할루시네이션(도메인 2·4) · 사람 검토 ↔ human-in-the-loop·사람 평가(태스크 3.4, 도메인 4) · 민감 정보 넣지 않기 ↔ 데이터 프라이버시(도메인 5).
